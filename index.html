CSR, SSR, SSG… ça veut dire quoi ?

CSR — Rendu dans le navigateurLe JavaScript construit l’écran côté utilisateur. Typique des interfaces SPA interactives.
SSR — Rendu côté serveurLe serveur génère le HTML au moment de la demande : pratique pour certaines pages dynamiques ou personnalisées.
SSG — Génération statiqueLes pages sont fabriquées lors du build et servies ensuite par un CDN, sans serveur de rendu à chaque visite.

Ces mots décrivent le rendu du site web, pas le choix REST, GraphQL ou BFF. Voir le glossaire complet ↓

02 / Principes de décision

Trois distinctions essentielles

BFF ≠ API Gateway

Un BFF porte un contrat adapté à une expérience et souvent la session OAuth. Une gateway est un point d'entrée transversal : elle peut coexister avec le BFF sans le remplacer.

GraphQL ≠ BFF obligatoire

Une API GraphQL peut être directement mutualisée, ou constituer un BFF dédié. Le choix du protocole et celui de la frontière applicative sont indépendants.

Serverless ≠ sans backend

Le CDN peut servir la SPA, tandis que des fonctions exécutent le BFF REST ou GraphQL. « Serverless » décrit avant tout un modèle d'exécution et d'exploitation.
